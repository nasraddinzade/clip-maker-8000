# Реклама по каркасу «сайт принимает заказы». Два захода вместо десятков кругов (Scent Harbor, 19.11.2026)

Для рекламы владельцу бизнеса, когда человек выбрал каркас `reference/ad-template-site-order.md`. Бриф по каркасу уже закрывает всё, кроме переменных. Остановки сворачиваются в одну по решению человека: он не хочет смотреть каждый шаг. Первый заход даёт готовый ролик, второй правки по просмотру на телефоне. Правило потолка кругов: раскадровка не больше двух кругов, ревьюер один раз на готовый ролик (`reference/lessons.md`, 2026-11-19).

Переменные, которые человек даёт до первого захода: бизнес и название, товары, событие (заказ, запись, бронь), трек (файл и лицензия), логотип студии (PNG, лучше на прозрачном фоне), строка карточки, канал связи, настоящий зритель для ревьюера. Страны и города не называть.

## Заход 1 (модель Opus)

```
Реклама по каркасу site-order, два захода. Человек отменил промежуточные остановки. Ты идёшь от раскадровки до готового ролика с музыкой и останавливаешься один раз, в конце. Сначала git pull в clip-maker-8000, прочитай reference/ad-template-site-order.md и lessons.md с последнего раздела про этот каркас.

Переменные: бизнес {…}, товары {…}, событие {…}, трек {…}, логотип {…}, строка карточки {…}, канал {…}.

Код не пиши с нуля: скопируй templates/ad-site-order/ в проект и иди по его README (config.json, захват, раскадровка, build_reel.sh, run_checks.sh).

Экономия лимитов. Захваты не переснимай без нужды. Рендери только изменённые такты. Один свежий ревьюер, один раз, на готовый ролик. Не перечитывай ненужные файлы. Отчёт до 30 строк.

Ход. Раскадровка по таблице тактов каркаса, не больше двух кругов, потом сразу аниматик под трек, ударные моменты на доли трека, карточка на смену фразы. Подписи крупные: заглавные не мельче 20 px в 360 по высоте, начертание насыщенное, контраст не ниже 7:1, не больше двух строк, одно ключевое слово цветом акцента, без плашек. Текст событий внутри экрана не мельче 12 px в 360. Итог у клиента 1,8 с с медленным наездом. Финал не повторяет хук, различие масштабом. Логотип только на карточке, цвет не менять, при контрасте ниже 3:1 менять фон под ним. Что показывает настоящий кабинет после «Принять» (статус, счётчик), то и показывай, пустое поле не оставляй. Громкость −14 ±1 LUFS, true peak не выше −1 dBTP. Страны и города нигде не называй.

Проверки: все из video-qa и каркаса, плюс участки без подписи по таймлайну из кода (не длиннее 1,5 с), буквы подписей и событий в 360, контраст, зоны Reels, обложка. Новые проверки сначала на плохом входе.

Ревьюер один, свежий, на готовый ролик, ему задан настоящий зритель {…}. Оценки по якорям. Отдельный вопрос, отличается ли финал от хука в 360 px. Правки по его замечаниям один раз, третьего круга нет. Критерий не выполнен, пиши одной строкой, решает человек.

Результат: ролик 1080×1920 H.264 + AAC, обложка, отчёт по video-qa, «Предлагаю в репозиторий», отдельно что человек проверяет на слух и на вкус на настоящем телефоне.
```

## Заход 2 (Sonnet, если правки мелкие; Opus, если меняется композиция)

Человек смотрит ролик на телефоне со звуком и собирает ВСЕ замечания в одном сообщении.

```
Реклама по каркасу site-order, заход 2. Правила и экономия лимитов как в заходе 1. Захваты не переснимать, звук не трогать, файл писать под новым именем. Исправь только то, что ниже, ничего больше.
1. …
2. …
Пересведи, проверки только по изменённому, кроп до и после на каждую правку, в 360 px. Ревьюера не запускай. Экспорт, обложка, если менялась. Отчёт до 15 строк.
```

Что показал Scent Harbor. Все числовые проверки прошли, а подписи на настоящем телефоне оказались мелкими: порог 12 px в 360 был принят за цель. Поэтому подписи с первого захода делают крупными (пункт про подписи выше), а человек смотрит на телефоне до последнего рендера.
