# Проверки и отчёт

Скрипты в `tools/`, описание в `tools/README.md`.

## Обязательные проверки

Это общие проверки. Добавочные для типа ролика лежат в приёмке навыка типа: `video-ad-craft` (красота, устройства, запрещённые слова, креативная оценка), `video-explainer-craft` (источники, перепроверка фактов), `video-essay-craft`.

| Проверка | Инструмент | Критерий |
|---|---|---|
| Длины и формат | `audio_check.py lengths` | 1080×1920, 30 fps, видео равно звуку ±1 кадр |
| Громкость | `audio_check.py loud` | −14 ±1 LUFS, true peak не выше −1 dBTP |
| Стыки звука | `audio_check.py joints` | тишина голоса на стыке, отрезки по 3 с прослушаны человеком |
| Кадры каждые 2 с | `frames_every.py` | лист просмотрен, первый кадр не пустой |
| Пустые кадры | доля пикселей темнее бумаги по каждому кадру | нет интервала дольше 0,5 с ниже порога, порог подобран на заведомо пустых кадрах |
| Кропы 3×3 | `crops3x3.py` | кадр из середины каждой сцены, все 9 клеток описаны |
| Переходы | 8 кадров на переход | нет полос, обрывов, наложений на подпись |
| Ключевые события | кроп 100 % каждого события, 5 кадров в секунду | событие читается, не перекрыто другим элементом, после любой его правки смотрится заново |
| Подписи | `caption_margins.py --ui <площадка>` | 0 нарушений во всех кадрах, подпись появляется не позже 0,3 с после начала фразы |
| Зоны элементов | рамки ключевых элементов из рендера | 0 нарушений в покое, переезды не считаются |
| Телефон | кадры с подписями в 360 px по ширине | подпись читается, штрих не тоньше 1 px |
| Обложка | обложка в 120 px по ширине (плитка профиля) | название читается, главный знак целый |
| Вспышки | `flash_detector.py` | 0 вспышек, прогон на заведомо плохом входе находит хотя бы одну |
| Движение | `motion.py` и таблица событий | событие хотя бы раз в 2 с для эссе, в 3 с для объяснялки, неподвижный кадр не дольше 0,7 с для рекламы, кроме отдыха из таблицы ритма, метрика только сигнал тревоги |
| Ударения | таблица из словаря | показана человеку |

Каждую новую проверку сначала прогони на заведомо плохом входе. Детектор, который ни разу не сработал, ничего не доказывает. Детектор, который по всему ролику даёт тысячи срабатываний, тоже ничего не доказывает. Запускай такой на участках, где ищешь конкретный дефект.

Файлы для прослушивания человеком проверяй скриптом на перекрытия кусков и на обрывы посреди слов до отправки. Отдавай цельные фразы или целую дорожку с таймкодами.

## Ревью свежим взглядом

Перед показом полного ролика запусти субагента, который не видел твоих правок. Дай ему только пути к листам, кропам и брифу. Попроси найти то, что заказчик попросит переделать, со ссылками на номера кадров. Его находки включи в отчёт без смягчений.

До этого крути свой цикл правки, а не правь наугад.
- Смотри в трёх масштабах: лист всего ролика, полоса каждого кадра момента (переходы, удары), кроп в полном разрешении.
- Ставь себе оценки 1–10 по осям: хук, читаемость на телефоне, движение, разнообразие, композиция, верность бренду и материалу, синхрон со звуком. Чини три худших пункта, пиши строку в `review_log.md` (оценки, три проблемы с таймкодами, что изменил). Не меньше трёх кругов для нового ролика. Если два круга подряд не подняли самую низкую оценку, остановись и доложи, что мешает.
- Для рекламы и объяснялки после двух-трёх кругов запусти четырёх критиков параллельно на 20 кадрах (пики и переходы): композиция, текст и читаемость, повествование и темп, верность бренду и настоящему продукту. Сведи их в один план правок.
Подробности в `reference/motion-craft.md`, раздел 6. Эти оценки твои рабочие, «Креативную оценку» всё равно ставит свежий субагент.

## Формат отчёта

```
Статус: готово / готово с исключениями / не готово
Что показываю: пути к файлам
Что изменилось: пункты, у каждого кроп или кадр «до/после»
Проверки: проверка → результат → критерий
НЕ прошло: пункты с цифрами (обязательно, даже если пусто)
НЕ проверено мной: что требует глаз или ушей человека
Отличия от плана: пункты
Вопрос: одно решение, которое нужно от человека
```

## Запреты

- Не пиши «исправлено» без кропа в 100 % того места.
- Не подгоняй решение под порог метрики.
- Не прячь непрошедшие проверки в середину текста.
