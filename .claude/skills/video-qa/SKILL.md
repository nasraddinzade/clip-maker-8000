# Проверки и отчёт

Скрипты в `tools/`, описание в `tools/README.md`.

## Обязательные проверки

Это общие проверки. Добавочные для типа ролика лежат в приёмке навыка типа: `video-ad-craft` (красота, устройства, запрещённые слова, креативная оценка), `video-explainer-craft` (источники, перепроверка фактов), `video-essay-craft`.

| Проверка | Инструмент | Критерий |
|---|---|---|
| Длины и формат | `audio_check.py lengths` (печатает размер и fps, код ошибки только по длинам) | 1080×1920 и 30 fps сверь глазами по выводу, видео равно звуку ±1 кадр |
| Размеры элемента | крайние точки элемента за всю сцену, с камерой | ширину и отступы не мерить по одной строке или одному кадру |
| Громкость | `audio_check.py loud` | −14 ±1 LUFS, true peak не выше −1 dBTP |
| Стыки звука | `audio_check.py joints` | тишина голоса на стыке, отрезки по 3 с прослушаны человеком |
| Кадры каждые 2 с | `frames_every.py` | лист просмотрен, первый кадр не пустой |
| Пустые кадры (эссе и рисованные стили на бумаге) | доля пикселей темнее бумаги по каждому кадру | нет интервала дольше 0,5 с ниже порога, порог подобран на заведомо пустых кадрах Задуманная пустота эссе из `brief.md` не дефект (`CLAUDE.md`, «Темп»). Для тёмного фона рекламы считай долю кадра, где виден главный элемент. |
| Кропы 3×3 | `crops3x3.py` | кадр из середины каждой сцены, все 9 клеток описаны |
| Переходы | 8 кадров на переход | нет полос, обрывов, наложений на подпись |
| Бледные прямоугольники | кропы фона и мест под подписями с автоконтрастом | нет прямых краёв у размывок, плашек и масок, особенно после правок фона |
| Ключевые события | кроп 100 % каждого события, 5 кадров в секунду | событие читается, не перекрыто другим элементом, после любой его правки смотрится заново |
| Подписи | `caption_margins.py --ui <площадка> --elements <рамки устройств>` | 0 нарушений во всех кадрах, подпись не закрыта ни одним устройством, подпись появляется не позже 0,3 с после начала фразы (это скрипт не проверяет, он не знает голос: сверь таймкоды подписей с таймкодами фраз отдельным скриптом в проекте) |
| Зоны элементов | рамки того, что надо прочитать или узнать (знаки, фигуры, печати, логотипы), из рендера | 0 нарушений в покое; у эссе и объяснялки переезды не считаются, у рекламы считаются и переезды (`video-ad-craft`, «Приёмка»). Фон и продолжение картинки под кнопками допустимы. Ключевой элемент задаётся по тактам: после наезда на значок проверка не требует цену и кнопку, ушедшие из кадра. Размер текста меряй по высоте самих букв, а не по рамке значка или кружка (кружок 13,7 px, цифра в нём 6 px, Scent Harbor, look10) |
| Рамки для проверок | рамки подписей и элементов пересобираются из тех же параметров, что рендер этого круга | устаревший экспорт рамок даёт ложные проходы и провалы (Scent Harbor, look13) |
| Обрезанные слова (ролики с захватами сайта) | рамки слов из DOM захвата, спроецированные в кадр | 0 слов наполовину за краем кадра или под предметом сцены, допуск 6 px на межстрочный интервал. Обрезанное «УТИК» или «Брен» читается как ошибка. Проверку сначала на плохом входе |
| Телефон | кадры с подписями в 360 px по ширине | подпись читается, штрих не тоньше 1 px |
| Обложка | обложка в 120 px по ширине, в плитке 3:4 и 1:1 | название читается в обеих, главный знак целый |
| Вспышки | `flash_detector.py` | 0 вспышек, прогон на заведомо плохом входе находит хотя бы одну. Срабатывание разбирай кропом: в рамку знака может войти соседний элемент (в v4 «Пяти колец» дуга энсо), тогда это не вспышка знака |
| Движение | `motion.py` и таблица событий | событие хотя бы раз в 2 с для эссе, в 3 с для объяснялки, неподвижный кадр не дольше 0,7 с для рекламы, кроме отдыха из таблицы ритма, метрика только сигнал тревоги Задуманная пауза эссе из `brief.md`, раздел «Решения по сценам», событий не требует (`CLAUDE.md`, «Темп»).. В эссе удержание готового образа до 3 с событием не считается, но и дырой тоже, отрисовку ради метрики не растягивай |
| Не нейросеть | проверка «угадай нейросеть» из `reference/slop-patterns.md` (как зритель, в масштабе телефона; блокируют только признаки «заметит зритель») свежим субагентом по листу кадров, кропам и подписям | ни одного признака, есть ответ «что есть только у этого заказчика или темы» |
| Ударения | таблица из словаря | показана человеку |

Каждую новую проверку сначала прогони на заведомо плохом входе. Детектор, который ни разу не сработал, ничего не доказывает. Детектор, который по всему ролику даёт тысячи срабатываний, тоже ничего не доказывает. Запускай такой на участках, где ищешь конкретный дефект.

Файлы для прослушивания человеком проверяй скриптом на перекрытия кусков (скрипт пишется в проекте, в `tools/` его нет) и на обрывы посреди слов до отправки. Отдавай цельные фразы или целую дорожку с таймкодами.

## Ревью свежим взглядом

Бюджет акцента в отчёте приводи всеми метриками, что считал, с допуском и цветом. В отчёте у каждой правки укажи правило и его источник (общее, тип ролика, площадка). Правку по правилу другого типа помечай отдельно с причиной.

Перед запуском ревьюера сверь `brief.md` со списком правок этого круга, иначе ревьюер примет новое решение за дефект.

Перед показом полного ролика запусти субагента, который не видел твоих правок. Дай ему только пути к листам, кропам и брифу. В брифе раздел «Решения по сценам» с тем, что человек уже принял, каждая строка с меткой [РЕШЕНИЕ БРИФА]: ревьюер может спорить с решением, но помечает это как спор, а не как дефект. Попроси найти то, что заказчик попросит переделать, со ссылками на номера кадров. Его находки включи в отчёт без смягчений. Проси его отдельно пометить, какие находки появились из-за правок этой версии, а какие были раньше.

До этого крути свой цикл правки, а не правь наугад.
- Смотри в трёх масштабах: лист всего ролика, полоса каждого кадра момента (переходы, удары), кроп в полном разрешении.
- Ставь себе оценки 1–10 по осям: хук, читаемость на телефоне, движение, разнообразие, композиция, верность бренду и материалу, синхрон со звуком. Чини три худших пункта, пиши строку в `review_log.md` (оценки, три проблемы с таймкодами, что изменил). Не меньше трёх кругов для нового ролика. Если два круга подряд не подняли самую низкую оценку, остановись и доложи, что мешает. Если одно и то же замечание к главной идее (что предлагают, общий вид, образ сцены) повторяется два круга подряд, мелочи дальше не правь, вынеси человеку решение уровня концепта или стиля с 2–3 вариантами (для всех типов; урок Scent Harbor, look6–look11). Субагент находит замечания на любой версии, поэтому после четырёх-пяти кругов полного ролика предложи человеку последний круг и экспорт, а решение о публикации оставь ему.
- Для рекламы и объяснялки после двух-трёх кругов запусти четырёх критиков параллельно на 20 кадрах (пики и переходы): композиция, текст и читаемость, повествование и темп, верность бренду и настоящему продукту. Сведи их в один план правок.
Подробности в `reference/motion-craft.md`, раздел 6. Эти оценки твои рабочие, «Креативную оценку» всё равно ставит свежий субагент.

## Формат отчёта

```
Статус: готово / готово с исключениями / не готово
Что показываю: пути к файлам
Что изменилось: пункты, у каждого кроп или кадр «до/после»
Проверки: проверка → результат → критерий
НЕ прошло: пункты с цифрами (обязательно, даже если пусто)
НЕ проверено мной: что требует глаз или ушей человека
Отличия от плана: пункты
Предлагаю в репозиторий: урок, доказательство, какое правило и где, тип ролика (или «нечего предложить»). Сам не коммить
Вопрос: одно решение, которое нужно от человека
```

## Запреты

- Не пиши «исправлено» без кропа в 100 % того места.
- Не подгоняй решение под порог метрики.
- Не прячь непрошедшие проверки в середину текста.
